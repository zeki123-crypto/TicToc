# 🤖 Деплой TicToc на Bothost.ru

[Bothost.ru](https://bothost.ru) — российский хостинг ботов с бесплатным
тарифом, автодеплоем из Git, Redis и поддержкой **Dockerfile**.

> ⭐ **Важно:** деплой через **Dockerfile** — основной и рекомендуемый способ,
> потому что наш `Dockerfile` ставит **ffmpeg**, без которого не работают
> уникализация и водяные знаки. Нативный Python-режим Bothost ffmpeg может не
> содержать.

---

## Что уже готово в репозитории

| Файл | Для чего |
| --- | --- |
| `Dockerfile` | Основной способ запуска (Python + **ffmpeg** + шрифты) |
| `main.py` | Точка входа для нативного режима (`python main.py`) |
| `Procfile` | `worker: python -m app` — команда запуска |
| `runtime.txt` | Версия Python (`python-3.12`) для нативного режима |
| `requirements.txt` | Зависимости |

---

## Шаг 1. Токен бота

В Telegram у **@BotFather**: `/newbot` → скопируй токен `123456789:AA...`.

---

## Шаг 2. Создать проект на Bothost

1. Зарегистрируйся на https://bothost.ru и войди.
2. Создай новый проект → **Деплой из Git** → подключи GitHub.
3. Выбери репозиторий **`zeki123-crypto/TicToc`** и ветку
   **`claude/telegram-video-download-bot-gab72t`** (или `main` после мержа).

---

## Шаг 3. Выбрать способ сборки — **Docker** (рекомендуется)

В настройках проекта выбери тип окружения **Dockerfile** (Bothost найдёт наш
`Dockerfile` в корне).

> Так в контейнер попадёт ffmpeg → все функции бота (скачивание + обработка)
> работают полностью.

Если Docker по какой-то причине недоступен на твоём тарифе — см. раздел
«Нативный режим» ниже (но там обработка видео может не работать).

---

## Шаг 4. Добавить Redis (рекомендуется)

В панели добавь аддон **Redis**. Bothost обычно прокидывает переменную
`REDIS_URL` — наш бот читает её автоматически и сам включает Redis-хранилище.

Без Redis бот тоже запустится (в памяти), но состояние сбросится при
перезапуске.

---

## Шаг 5. Переменные окружения

В настройках проекта (Variables / Переменные) добавь:

| Переменная | Значение | Обязательно |
| --- | --- | --- |
| `BOT_TOKEN` | токен из @BotFather | ✅ |
| `REDIS_DSN` | URL Redis (или используй `REDIS_URL` от аддона) | если есть Redis |
| `STORAGE_TYPE` | `redis` (или `memory` без Redis) | — |
| `MAX_FILE_SIZE_MB` | `50` | — |
| `MAX_DURATION_SECONDS` | `1800` | — |
| `MAX_CONCURRENT_JOBS` | `2` | — |
| `LOG_LEVEL` | `INFO` | — |

> Если аддон Redis даёт `REDIS_URL` — отдельный `REDIS_DSN` можно не задавать,
> бот подхватит `REDIS_URL` сам.

---

## Шаг 6. Запуск

1. Сохрани настройки → Bothost соберёт образ и запустит бота.
2. Открой **Логи**. Должно появиться:

   ```
   storage.redis  dsn=redis://...
   bot.started    username=<твой_бот>  id=...
   ```

3. Найди бота в Telegram, нажми **Start**, кинь ссылку на TikTok 🎉

При каждом `git push` в выбранную ветку Bothost пересоберёт и перезапустит
бота автоматически.

---

## Нативный режим (без Docker) — запасной вариант

Если выбираешь окружение **Python** (не Dockerfile):

- **Команда запуска:** `python -m app` (или `python main.py`).
- Bothost сам поставит зависимости из `requirements.txt`.
- `runtime.txt` задаёт версию Python.

⚠️ **Ограничение:** в нативном режиме **может не быть ffmpeg**. Тогда:
- скачивание видео работает,
- а уникализация и водяные знаки выдадут ошибку «ffmpeg is not installed».

Если нужен полный функционал — используй **Docker-режим** (Шаг 3) или уточни у
поддержки Bothost, доступен ли ffmpeg на нативном окружении.

---

## Частые вопросы

**В логах «ffmpeg is not installed»**
→ Ты на нативном режиме без ffmpeg. Переключись на **Dockerfile**-сборку.

**`storage.memory`, хотя добавил Redis**
→ Переменная Redis не привязана. Проверь `REDIS_DSN`/`REDIS_URL` в настройках.

**Бот не отвечает, ошибка токена**
→ Проверь `BOT_TOKEN` (целиком, без пробелов).

**Файл «слишком большой»**
→ Лимит Telegram 50 МБ. Для TikTok обычно ок.
