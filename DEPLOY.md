# 🚀 Деплой TicToc на Railway

Пошаговая инструкция, как поднять бота на [Railway](https://railway.app).
Railway сам соберёт Docker-образ из репозитория и запустит бота 24/7.

> Время на всё: ~10 минут. Нужен только токен бота от @BotFather.

---

## Что уже готово в репозитории

| Файл | Зачем |
| --- | --- |
| `Dockerfile` | Railway собирает образ по нему (Python + ffmpeg + шрифты) |
| `railway.json` | Конфиг билда/рестарта для Railway |
| `.dockerignore` | Уменьшает контекст сборки |
| `requirements.txt` | Зависимости Python |

Бот сам подхватывает Redis-плагин Railway: он умеет читать переменную
`REDIS_URL` и автоматически переключается на Redis-хранилище.

---

## Шаг 1. Получить токен бота

1. Открой в Telegram **@BotFather** → `/newbot`.
2. Задай имя и username.
3. Скопируй **токен** вида `123456789:AA...` — он понадобится дальше.

---

## Шаг 2. Создать проект на Railway

1. Зайди на [railway.app](https://railway.app) и войди через GitHub.
2. **New Project** → **Deploy from GitHub repo**.
3. Выбери репозиторий **`zeki123-crypto/TicToc`**.
4. На вкладке **Settings → Source** выбери ветку
   **`claude/telegram-video-download-bot-gab72t`** (или ту, в которую смержишь
   код).

Railway найдёт `Dockerfile` и начнёт сборку автоматически.

---

## Шаг 3. Добавить Redis

1. В проекте нажми **New** → **Database** → **Add Redis**.
2. Railway создаст сервис Redis и переменную `REDIS_URL`.

> Redis нужен, чтобы состояние бота (FSM) переживало перезапуски и бот можно
> было масштабировать. Без него можно обойтись (`STORAGE_TYPE=memory`), но для
> прода рекомендуется Redis.

---

## Шаг 4. Прописать переменные окружения

Открой сервис бота → вкладка **Variables** → добавь:

| Переменная | Значение | Обязательно |
| --- | --- | --- |
| `BOT_TOKEN` | токен из @BotFather | ✅ |
| `REDIS_DSN` | `${{Redis.REDIS_URL}}` | ✅ (если добавил Redis) |
| `MAX_FILE_SIZE_MB` | `50` | — |
| `MAX_DURATION_SECONDS` | `1800` | — |
| `MAX_CONCURRENT_JOBS` | `2` | — |
| `THROTTLE_RATE` | `2.0` | — |
| `LOG_LEVEL` | `INFO` | — |

> ⚠️ `${{Redis.REDIS_URL}}` — это **ссылка на переменную** соседнего сервиса
> Redis (Railway подставит её сам). Просто впиши её именно так. Бот при наличии
> валидного Redis-URL сам включит режим `STORAGE_TYPE=redis`.

---

## Шаг 5. Запуск

1. После сохранения переменных Railway передеплоит сервис автоматически
   (или нажми **Deploy**).
2. Открой вкладку **Deployments → Logs**. Должно появиться:

   ```
   storage.redis  dsn=redis://...
   bot.started    username=<твой_бот>  id=...
   ```

3. Найди бота в Telegram, нажми **Start** и кинь ссылку на TikTok-видео 🎉

---

## Обновление бота

Railway деплоит автоматически при каждом пуше в выбранную ветку.
Просто `git push` — и через пару минут обновлённый бот в проде.

---

## Частые вопросы

**Бот не отвечает / в логах `TokenValidationError`**
→ Проверь `BOT_TOKEN` (без пробелов, целиком).

**В логах `storage.memory`, хотя добавил Redis**
→ Переменная `REDIS_DSN` не привязана. Убедись, что стоит
`${{Redis.REDIS_URL}}` и Redis-сервис в том же проекте.

**Файл не отправляется, "слишком большой"**
→ Лимит Telegram для ботов — 50 МБ. Это нормально для TikTok. Для больших
файлов нужен self-hosted Bot API сервер (выходит за рамки Railway-деплоя).

**Можно ли запускать несколько экземпляров?**
→ Да, состояние в Redis это позволяет. Но Telegram long-polling должен вести
**один** экземпляр на токен — не поднимай `numReplicas > 1` для одного бота.

**Сколько стоит?**
→ У Railway есть стартовый бесплатный кредит; дальше — оплата по потреблению.
Бот лёгкий, ffmpeg грузит CPU только в момент обработки.

## Альтернатива: деплой через Railway CLI

```bash
npm i -g @railway/cli
railway login
railway link            # выбрать проект
railway up              # собрать и задеплоить текущую ветку
railway variables set BOT_TOKEN=123:ABC
railway logs            # смотреть логи
```
